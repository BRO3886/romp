# Verify is always explicit — never guessed at runtime

romp does not infer the verification command from the language or toolchain in a repo. The verify command is a per-repo contract committed in `romp.toml` under `[verify]`; without it romp refuses to run and points at `romp init`. Language detection happens once, at init, as a seeded suggestion the human confirms (`go.mod` → `go test ./... -count=1`, `Cargo.toml` → `cargo test`, `package.json` → `npm test`, `pyproject.toml` → `pytest`, `Makefile` → `make test`). Detection at runtime is rejected because a silently wrong test command produces a false "done" — a plausible PR that solves the wrong problem — which is worse than failing loudly; monorepos and custom runners make any runtime heuristic wrong often enough to matter.
